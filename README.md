# 유튜브 구간 편집기

> **https://github.com/plnman/Vidoe_clip**

유튜브 링크나 **내 컴퓨터의 영상 파일**에서 원하는 구간만 잘라 하나로 이어붙여 줍니다.
구간은 제미나이 같은 도구가 정리해 준 텍스트를 **그대로 붙여넣으면** 됩니다.

만들어진 영상을 보면서 구간 시작·끝을 다시 손보고 재렌더할 수 있고,
그때는 **다시 다운로드하지 않습니다.**

두 가지 방식으로 쓸 수 있습니다.

| | 설치형 앱 | 직접 실행 |
|---|---|---|
| 준비물 | 없음 | Python + ffmpeg |
| 쓰는 법 | 설치 파일 실행 → 창이 뜸 | `run.bat` / `./run.sh` |
| 다른 기기에서 접속 | — | `--lan`, `--share` 가능 |

처음이라면 설치형 앱이 편합니다. 집 PC에서 돌리고 노트북으로 붙어 쓰려면 직접 실행 쪽입니다.

## 왜 이렇게 동작하나

시중의 "유튜브 자르기" 도구가 느리고 파일이 큰 이유는 두 가지입니다.
전체 영상을 받고, 최고 화질로 받기 때문입니다. 이 앱은 반대로 갑니다.

| | 흔한 방식 | 이 앱 |
|---|---|---|
| 다운로드 범위 | 영상 전체 | 쓸 구간 ± 여유분만 |
| 화질 | 최고 화질 고정 | 지정한 상한까지만 |
| 구간 수정 후 | 처음부터 다시 | 받아둔 파일로 재렌더만 |

1시간짜리에서 2분만 쓴다면 2분어치(+여유분)만 내려받습니다.

### 여유분(pad)

각 구간을 앞뒤로 기본 10초씩 더 받아둡니다. 그래서 편집 화면에서
시작·끝을 몇 초 당기거나 미는 조정은 **네트워크를 전혀 쓰지 않고** 즉시 반영됩니다.
여유분 밖으로 나가면 그 구간만 표시되고, 버튼 하나로 그 부분만 다시 받습니다.

영상 어디든 자유롭게 편집하고 싶으면 `전체 영상 받기`를 켜세요.
용량은 크지만, 그다음부터는 어떤 편집도 재다운로드가 없습니다.

### 받는 중에 뜨는 시간대가 내가 넣은 구간과 다를 때

정상입니다. 두 가지가 겹쳐서 그렇습니다.

- **여유분**이 앞뒤로 붙습니다 (`3:15-4:12` → `3:05~4:22`)
- 그렇게 넓어진 것끼리 **닿으면 한 번에 받습니다.** `3:15-4:12`와 `4:30-7:05`은
  사이가 18초뿐이라 따로 받으면 같은 데이터를 두 번 받는 셈이 됩니다

그래서 `구간 1–2 · 여유분 포함 3:05~7:15 받는 중 (1/10)` 처럼 뜹니다.
**어느 구간을 받는 중인지** 앞에 적어 두었으니 그것을 보시면 됩니다.
구간 12개가 다운로드 10회로 줄었다는 뜻이고, 편집 화면에는 12개 그대로 나옵니다.

### 구간 받기가 느릴 때 — 전체 받기가 더 빠릅니다

구간만 받을 때는 컷 지점을 정확히 맞추려고 **그 구간을 다시 인코딩합니다**
(yt-dlp의 `--force-keyframes-at-cuts`). 이게 없으면 파일이 요청한 시각보다 앞에서
시작해서 **완성본의 모든 구간이 어긋납니다.** 정확도를 얻는 대신 느립니다.

그래서 쓸 구간이 많아 **영상의 절반을 넘으면 전체 영상 받기가 오히려 빠릅니다.**
전체 받기는 재인코딩 없이 그냥 내려받기 때문입니다. 이 경우 화면이 알려주고
버튼도 함께 보여줍니다.

기준은 `2단계`의 `받을 양`입니다 — 여유분과 병합까지 반영한 실제 다운로드 양입니다.

## 내 컴퓨터의 영상 파일 자르기

유튜브 링크 대신 이미 가진 영상 파일도 됩니다. 1단계에서 `내 영상 파일` 탭을 누르세요.
받을 것이 없으니 **어느 구간이든 바로 편집**됩니다. 여유분을 신경 쓸 일도 없습니다.

여는 방법은 세 가지입니다.

| 방법 | 언제 |
|---|---|
| `파일 선택` | 설치형 앱에서. 익숙한 파일 선택 창이 뜹니다 |
| 파일을 끌어다 놓기 | 브라우저에서 쓸 때 |
| 파일 경로 붙여넣기 | 앱을 켜 둔 그 PC의 파일일 때 — **가장 빠릅니다** |

경로로 열면 **파일을 복사하지 않고 있는 자리에서 그대로** 씁니다. 10GB짜리를 열어도
기다릴 일이 없고, 원본은 전혀 건드리지 않습니다. 작업을 지워도 원본은 남습니다.

노트북에서 집 PC의 앱에 접속해 쓰는 경우에는 경로를 쓸 수 없습니다(그 파일이 노트북에
있으니까요). 그때는 끌어다 놓아 올리면 됩니다. 기본 상한은 8GB입니다.

읽을 수 있는 형식은 mp4 · mov · mkv · webm · avi · wmv · flv · m4v · mpg · ts 등과
mp3 · m4a · wav · flac 같은 소리 파일입니다. 소리만 있는 파일도 구간을 잘라 이어붙일 수 있습니다.

## 설치해서 쓰기 (Windows)

설치 파일 하나만 실행하면 됩니다. Python도 ffmpeg도 필요 없습니다.

1. `YoutubeClipper-setup.exe`를 실행합니다 (약 79MB)
2. 처음 열 때 파란 경고창이 뜨면 `추가 정보` → `실행` 을 누릅니다
   — 유료 인증서로 서명하지 않아서 뜨는 것이고, 한 번만 하면 됩니다
3. 설치가 끝나면 창이 열립니다. 그 안에서 그대로 쓰면 됩니다

관리자 권한은 필요 없고, 지울 때는 `설정 → 앱`에서 제거하면 작업 파일까지 같이 지워집니다.

직접 만들려면 (윈도우에서, 윈도우용만 만들어집니다):

```powershell
.\packaging\build.ps1 -Installer
```

**유튜브가 갑자기 안 될 때** — 유튜브는 가끔 규칙을 바꿉니다. 그럴 때 앱을 다시 설치할
필요 없이, 화면 맨 아래 `관리`에서 `업데이트`를 누르고 앱을 껐다 켜면 됩니다.

**앱이 안 뜰 때** — 무엇 때문인지 여기에 적힙니다.

```
%LOCALAPPDATA%\YoutubeClipper\app.log
```

탐색기 주소창에 그대로 붙여넣으면 열립니다. 서버가 끝내 못 뜨면 원인을 담은
알림창도 함께 뜹니다.

## 빠른 시작 (직접 실행)

ffmpeg만 미리 설치하면 됩니다.

| OS | 설치 | 실행 |
|---|---|---|
| macOS | `brew install ffmpeg` | `./run.sh` |
| Windows | `winget install Gyan.FFmpeg` | `run.bat` (더블클릭해도 됩니다) |
| Linux | `sudo apt install ffmpeg` | `./run.sh` |

처음 실행하면 가상환경을 만들고 의존성을 받느라 1~2분 걸립니다. 그다음부터는 바로 뜹니다.
실행하면 접속 주소를 화면에 찍어 줍니다 → http://127.0.0.1:8000

Docker를 쓴다면 `docker compose up -d` 한 줄이면 됩니다.

## 집 PC와 노트북, 둘 다에서 쓰기

두 가지 방법이 있습니다. 목적에 따라 고르세요.

### 방법 A — 두 기기에 각각 설치 (간단하고 확실)

각 컴퓨터에 이 폴더를 두고 `./run.sh`(또는 `run.bat`)를 돌립니다.
서로 독립적이라 상대 기기가 꺼져 있어도 됩니다. 작업 중이던 프로젝트는 공유되지 않습니다.

### 방법 B — 집 PC에서만 돌리고 노트북 브라우저로 접속

집 PC에서 `--lan`을 붙여 실행하면 같은 공유기에 있는 다른 기기에서도 접속됩니다.

```bash
CLIPPER_PASSWORD=원하는비밀번호 ./run.sh --lan      # macOS / Linux
set CLIPPER_PASSWORD=원하는비밀번호 && run.bat --lan  # Windows
```

실행하면 이렇게 알려 줍니다.

```
  이 컴퓨터에서:  http://127.0.0.1:8000
  같은 공유기의 다른 기기에서:  http://192.168.0.12:8000
```

아래 주소를 노트북 브라우저에 치면 됩니다. 무거운 다운로드·인코딩은 집 PC가 하고
노트북은 화면만 띄우므로, 노트북 성능이나 배터리와 무관하게 돌아갑니다.

### 방법 C — 인터넷 어디서나 쓰는 공개 주소

집 PC에서 `--share`로 띄우면 **https 주소가 발급**됩니다. 폰이든 회사든 그 주소로 들어갑니다.
공유기 포트를 열 필요도, 고정 IP도 필요 없습니다.

```bash
CLIPPER_PASSWORD=원하는비밀번호 ./run.sh --share      # macOS / Linux
set CLIPPER_PASSWORD=원하는비밀번호 && run.bat --share  # Windows
```

[cloudflared](https://github.com/cloudflare/cloudflared/releases)가 필요합니다
(`brew install cloudflared` / `winget install Cloudflare.cloudflared`).
계정 가입은 필요 없고, 실행하면 `https://xxxx-yyyy.trycloudflare.com` 같은 주소를 찍어 줍니다.

주의할 점 두 가지입니다.

- **링크만 알면 누구나 들어옵니다.** 그래서 `CLIPPER_PASSWORD` 없이는 아예 실행되지 않게 막아 뒀습니다.
- **터미널을 닫으면 주소도 사라집니다.** 매번 새 주소가 발급됩니다.
  고정 주소가 필요하면 Cloudflare 계정을 만들어 named tunnel을 쓰거나 Tailscale을 쓰세요.

유튜브 입장에서는 여전히 집 IP에서 들어오는 요청이라, 봇으로 막힐 일도 없습니다.

`--lan`으로 열 때는 `CLIPPER_PASSWORD`를 꼭 설정하세요. 안 하면 실행할 때 경고가 뜹니다.
설정해 두면 접속 시 비밀번호를 한 번 묻고 브라우저가 기억합니다.

### 클라우드 서버(VPS)는?

돌아가긴 하지만 유튜브가 데이터센터 IP를 봇으로 판단해 막는 일이 잦습니다.
VPS에 올릴 거라면 쿠키 설정이 사실상 필수입니다(바로 아래 참고).
집 PC가 있다면 방법 B가 더 안정적입니다.

### 잘 안 되면 — 진단부터

앱에서 오류가 났을 때, 어느 단계에서 막혔는지 한 번에 찍어 주는 명령이 있습니다.
짧은 영상 아무거나 하나로 돌려 보세요.

```bash
./.venv/bin/python -m app.doctor "https://youtu.be/영상ID"
```

```
[ OK ] ffmpeg 설치           ffmpeg version 6.1.1
[ OK ] yt-dlp 버전           2026.08.19
[ OK ] 링크 해석             https://www.youtube.com/watch?v=...
[ OK ] 영상 정보 조회        제목 · 12:34
[ OK ] 구간 다운로드         probe.mp4 · 830 KB
[ OK ] 받은 파일 확인        1280x720 30fps 5.0초 (요청 5초)
[ OK ] 잘라 이어붙이기       412 KB · 3.0초 (기대 3.0초)
```

실제로 5초를 받아 잘라 붙이는 것까지 해 봅니다. 실패하면 그 줄에 원인과 대처가 같이 나옵니다.
막히면 이 출력을 그대로 복사해서 물어보시면 됩니다. 화질을 바꿔 보려면 `--height 480`.

## 봇으로 막힐 때 — 자바스크립트 런타임

유튜브는 봇을 거르려고 자바스크립트 챌린지를 겁니다. yt-dlp는 이걸 실제 JS 런타임으로
풀어내는데, **기본 설정은 `deno` 하나만 찾습니다.** 이 앱은 설치된 런타임
(`deno` / `node` / `bun` / `quickjs`)을 자동으로 찾아 yt-dlp에 넘깁니다.

하나도 없으면 `Sign in to confirm you're not a bot` 오류가 날 수 있습니다.
아무거나 하나 설치하면 됩니다.

```bash
curl -fsSL https://deno.land/install.sh | sh   # deno
# 또는 이미 Node.js가 깔려 있다면 그대로 쓰입니다
```

`python -m app.doctor` 가 어떤 런타임이 잡혔는지 알려줍니다.

## 유튜브가 막을 때 (쿠키)

`Sign in to confirm you're not a bot` 오류가 나면 로그인 쿠키를 넘겨야 합니다.
브라우저 확장(예: "Get cookies.txt")으로 넷스케이프 형식 쿠키를 뽑아 저장한 뒤:

```bash
CLIPPER_COOKIES=/경로/cookies.txt ./run.sh
```

같은 PC에서 돌린다면 브라우저에서 직접 읽어올 수도 있습니다:

```bash
CLIPPER_COOKIES_FROM_BROWSER=chrome ./run.sh
```

## 제미나이에게 시킬 프롬프트

구간 정리를 맡길 때 이렇게 요청하면 결과를 그대로 붙여넣을 수 있습니다.

```
이 유튜브 영상에서 <원하는 주제>에 해당하는 구간만 골라줘.
각 줄을 아래 형식으로만 출력해. 설명이나 머리말은 붙이지 마.

시작 - 끝 제목

예시:
00:01:23 - 00:02:45 도입부 문제 제기
00:12:10 - 00:14:30 핵심 데이터 설명
```

형식이 조금 달라도 됩니다. 아래는 전부 읽습니다.

- `00:01:23 - 00:02:45 인트로`
- `1. 1:23~2:45 인트로` / `- 1:23 ~ 2:45`
- `1:23 -> 2:45`, `1:23부터 2:45까지`
- 마크다운 표: `| 00:01:23 | 00:02:45 | 인트로 |`
- JSON: `[{"start": "1:23", "end": "2:45", "title": "인트로"}]`
- 챕터 목록(시작 시각만): 다음 항목의 시작에서 자동으로 끊습니다

읽지 못한 줄은 이유와 함께 화면에 표시하니, 그 줄만 고치면 됩니다.

## 화면 흐름

1. **영상** — 유튜브 링크를 넣거나 `내 영상 파일` 탭에서 파일을 엽니다
2. **구간** — 텍스트를 붙여넣으면 몇 개 구간에 합계 몇 분인지 즉시 보여줍니다.
   화질·코덱·여유분을 정하고 `소스 준비`를 누르면 필요한 부분만 내려받습니다
   (내 파일이면 받을 게 없으니 `구간 확정`을 누르면 바로 3번으로 갑니다)
3. **편집** — 구간마다 재생해 보며 조정합니다.
   재생하다가 `여기부터`/`여기까지`를 누르면 그 지점으로 맞춰지고,
   `시작 −1초` 같은 버튼이나 시간 칸 직접 입력도 됩니다. 순서 변경·제외·삭제 가능
4. **만들기** — 저장 형식과 품질을 고르고 만듭니다. 결과를 바로 재생해 보고
   구간 버튼으로 각 구간 시작으로 건너뛸 수 있습니다. `PC에 저장`을 누르면 내려받습니다.
   마음에 안 들면 3번으로 돌아가 고치고 다시 만들면 됩니다 (재다운로드 없음)

## 저장 형식

기본은 **고른 구간을 하나로 이어붙인 MP4**입니다.

| 형식 | 쓰임 |
|---|---|
| MP4 (H.264) | 기본값. 어떤 기기·프로그램에서도 열립니다 |
| MP4 (H.265) | 같은 화질에 용량 절반. 최신 기기·프로그램에서만 열립니다 |
| WebM (VP9) | 용량이 작아 웹 업로드에 유리합니다 |
| GIF | 짧은 구간용. 소리는 빠지고 60초까지만 됩니다 |
| M4A | 소리만, 고음질 |
| MP3 | 소리만, 호환성 좋음 |

`이어붙이지 않고 구간마다 따로 저장 (ZIP)`을 켜면 구간마다 파일을 하나씩 만들어
`01_인트로.mp4`, `02_핵심요약.mp4` 처럼 이름 붙여 ZIP으로 묶어 줍니다.

품질은 `빠름 / 균형 / 고품질` 세 단계입니다. 인코딩 시간과 파일 크기가 함께 움직입니다.

## 구조

```
run.sh / run.bat  실행 스크립트 (--lan 을 붙이면 다른 기기에서도 접속 가능)
app/
  segments.py    자유 형식 구간 텍스트 -> 구조화 (표·JSON·챕터 목록까지)
  downloader.py  yt-dlp 래퍼. 구간만 받기, 화질 상한, 쿠키
  media.py       ffmpeg 래퍼. 정확 컷 + 이어붙이기를 한 번의 패스로
  projects.py    프로젝트 상태, 여유분 관리, 작업 큐 (내 파일 소스도 여기서)
  updater.py     yt-dlp를 앱과 따로 갱신
  desktop.py     앱 창으로 띄우기
  main.py        FastAPI 라우트
  static/        화면 (프레임워크 없는 HTML/CSS/JS)
packaging/       설치형 앱 만들기 (PyInstaller + Inno Setup)
```

핵심 규칙 하나: **소스 조각은 받은 그대로 보관하고, 컷은 렌더할 때만 한다.**
그래서 몇 번을 고쳐도 다운로드는 처음 한 번뿐입니다.

## 알아둘 점

- 다운로드는 유튜브 약관상 제한이 있습니다. 본인 영상이나 개인적 용도 범위에서 쓰세요.
- 진행 중인 라이브 스트림은 지원하지 않습니다.
- 작업 파일은 `CLIPPER_PROJECT_TTL` 이후 자동 삭제됩니다. 결과물은 그전에 내려받으세요.
- 렌더는 항상 재인코딩합니다(H.264/AAC). 구간 경계가 정확하고 어디서나 재생되는 대신,
  긴 완성본은 시간이 걸립니다. `빠름` 품질이 기본입니다.
- 화질을 1080p로 고르고도 낮게 나온다면, 그 영상 자체가 그 화질까지만 있는 것입니다.
  이 앱은 **있는 것 중에서 상한 이하로 가장 좋은 것**을 고릅니다.
- 작업하던 프로젝트는 앱을 끄면 사라집니다. 결과물은 그전에 내려받으세요.
- 설치형 앱은 코드 서명을 하지 않아 처음 열 때 윈도우 경고가 뜹니다
  (`추가 정보` → `실행`). 인증서가 유료라 지금은 그대로 둡니다.
- 함께 넣어 배포하는 ffmpeg이 GPL이라 이 프로그램도 GPL-3.0입니다(`LICENSE`).
